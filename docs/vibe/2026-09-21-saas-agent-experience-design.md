# SaaS Agent 体验与租户能力适配设计

日期：2026-09-21

## 背景

当前 SaaS 员工登录后的 Agent 使用体验存在六类问题：运行轨迹同时展开过多、资料页暴露本地角色、普通员工看到不需要配置的系统设置、退出登录跳转存在竞态、NewAPI 模型同步后缓存未刷新，以及租户后台维护的知识库没有完整呈现在 Agent 端且员工仍能看到知识库创建入口。

本次修改沿用现有认证、模型供应商和知识库数据边界，不新增能力中心、远程知识库代理或额外兼容层。

## 目标

1. Agent 执行期间只自动展开当前正在执行的工具或子智能体任务，回答结束后默认收起全部推理和工具轨迹。
2. SaaS 员工资料只展示部门名和员工姓名，不展示本地系统角色。
3. 普通 SaaS 员工的设置只保留账户资料，不显示基本设置、OCR 配置和沙盒环境变量。
4. 退出登录后稳定回到登录页，不被登录态路由守卫重定向回来。
5. SaaS 登录同步 NewAPI 模型列表后立即刷新共享模型缓存，使 Agent 模型列表读取到最新结果。
6. Agent 端展示租户后台维护且员工有权读取的知识库及目录；员工不能创建、修改或删除知识库和目录，命中 `manage_scope` 时可以管理文档。

## 非目标

- 不新增统一的 capabilities 接口。
- 不让 Agent 在每次知识库访问时实时代理调用租户后台。
- 不允许 SaaS 员工在 Agent 端管理知识库或目录。
- 不把基本设置、OCR 或沙盒环境变量改造成员工级配置。
- 不改变非 SaaS 本地管理员和超级管理员的现有功能边界。

## 设计

### 1. Agent 推理与任务展示

推理过程和工具调用继续保留手动展开能力，但自动状态统一为：

- 执行中：历史推理和已完成工具调用保持收起，只展开当前正在执行的一项工具或子智能体任务。
- 工具切换：前一项完成后立即收起，新一项成为唯一自动展开项。
- 回答完成、失败或取消：当前项也自动收起。
- 用户手动展开已完成项后，不因无关消息更新反复改写其选择。

当前任务依据现有消息状态、工具结果和 `activeSubagentToolCallIds` 判断，不增加新的后端运行状态协议。

### 2. SaaS 员工资料与设置

SaaS 员工身份以登录响应和 `/api/auth/me` 返回的 SaaS 字段为准。前端保存 `saas_mode`、员工姓名、部门名和员工编码，并采用以下展示规则：

| 场景 | SaaS 员工 | 本地管理员/超级管理员 |
| --- | --- | --- |
| 侧栏用户名称 | 员工姓名 | 用户名 |
| 资料摘要 | 部门名 + 员工姓名 | 用户名 + 本地角色 |
| 本地角色文案 | 隐藏 | 保留 |
| 账户资料 | 显示 | 显示 |
| 基本设置 | 隐藏 | 按现有管理员权限显示 |
| OCR 配置 | 隐藏 | 按现有管理员权限显示 |
| 沙盒环境变量 | 隐藏 | 按现有登录用户规则显示 |

后端 SaaS 用户仍使用内部 `role=user` 执行授权判断，但该实现角色不再作为员工可见资料。

### 3. 设置项职责

- 基本设置：系统默认对话、快速、Embedding、Rerank 模型及内容审查等部署级配置，由管理员维护。
- OCR 配置：文档解析所依赖的 OCR 引擎和服务凭证，由管理员维护。
- 沙盒环境变量：注入新建 Agent 沙盒的用户级外部服务变量；本次对 SaaS 员工隐藏，避免让普通员工承担运行环境配置。

页面只通过权限控制减少无关入口，不删除底层配置能力。

### 4. 退出登录

退出流程调整为：

1. 保存当前 token 供后端注销请求使用。
2. 立即清理前端用户状态、本地 token 和跨用户 Pinia 状态。
3. 使用保存的 token 尝试通知后端注销 SaaS 会话；失败只记录告警，不恢复本地登录态。
4. 使用路由 `replace` 进入 `/login`，避免历史记录返回受保护页面。

本地状态清理不得等待网络请求，消除路由守卫看到旧 token 的竞态。

### 5. NewAPI 模型同步与缓存

SaaS 登录继续从租户配置获取 NewAPI 地址和密钥，并从 `/v1/models` 同步模型清单到 `saas-newapi` 供应商。数据库事务提交成功后，使用现有模型缓存重建逻辑刷新共享缓存。

时序为：租户认证 -> 拉取租户模型配置 -> 同步供应商记录 -> 提交事务 -> 重建模型缓存 -> 返回登录结果。

模型列表页面和 Agent 选择器继续从共享缓存读取。普通页面刷新不主动请求 NewAPI，避免将外部服务延迟引入每次页面加载。若远端模型拉取失败，保留数据库中的上一版有效模型列表，不用空列表覆盖。

### 6. 租户知识库适配

租户后台和 Agent 使用同一套 PostgreSQL 知识库记录，`tenant_id` 确定租户归属，`share_config` 确定员工权限。员工列表查询只返回：

- `tenant_id` 与当前 SaaS 会话一致；
- `read_scope` 命中当前员工、部门或租户全局范围；
- 序列化结果包含详情页与目录展示需要的权限和类型字段。

员工操作权限如下：

| 操作 | `read_scope` | `manage_scope` | 管理员 |
| --- | --- | --- | --- |
| 查看知识库和目录 | 允许 | 允许 | 允许 |
| 检索和打开文档 | 允许 | 允许 | 允许 |
| 上传、移动、删除文档 | 禁止 | 允许 | 允许 |
| 创建、重命名、移动、删除目录 | 禁止 | 禁止 | 允许 |
| 创建、修改、删除知识库 | 禁止 | 禁止 | 允许 |

前端知识库列表对 SaaS 员工始终使用 accessible 接口，隐藏新建、编辑和删除知识库入口。详情路由不再用本地管理员角色拦截，而是依赖后端实际知识库权限；目录和文档按钮根据返回的有效权限显示。后端仍是最终授权边界。

## 错误处理

- SaaS 用户资料缺少部门时只展示员工姓名，不展示占位角色。
- 后端注销失败不阻止本地退出。
- NewAPI 拉取失败保留最后一次成功同步的模型配置，并记录可定位的服务端日志。
- 模型缓存刷新失败必须记录错误；登录仍可完成，但测试应覆盖正常刷新路径。
- 知识库跨租户访问继续返回 404，权限不足返回 403。

## 验收标准

- [ ] 执行 Agent 时同时最多只有一个当前任务自动展开，运行结束后全部默认收起。
- [ ] SaaS 员工菜单和账户资料显示部门名与员工姓名，不出现“管理员”“普通用户”等本地角色。
- [ ] SaaS 员工设置中不显示基本设置、OCR 配置和沙盒环境变量。
- [ ] 点击退出后 URL 和页面均稳定停留在 `/login`。
- [ ] NewAPI 增删模型后重新登录，Agent 模型选择器展示最新清单，无需重启 API 或 worker。
- [ ] SaaS 员工能看到租户后台维护且授权的知识库与目录。
- [ ] SaaS 员工看不到知识库及目录创建、编辑、删除入口。
- [ ] 只有命中 `manage_scope` 的员工能上传、移动和删除文档。
- [ ] 非 SaaS 管理员现有设置和知识库管理能力不回归。

## 测试计划

- 前端单元测试：推理/工具展开状态、SaaS 资料文案、设置标签可见性、知识库操作按钮和退出顺序。
- 后端单元或集成测试：SaaS 登录后的模型缓存刷新、模型同步失败保留旧清单。
- 后端集成测试：租户知识库列表过滤、目录读取、`read_scope`/`manage_scope` 文档权限以及跨租户拒绝。
- Docker 环境检查：运行相关前后端测试、Lint，并通过浏览器验证登录、退出、模型列表和知识库主路径。
