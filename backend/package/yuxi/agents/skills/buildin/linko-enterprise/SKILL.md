## 第1章 全局路由规则

先读 Linko MCP 工具的 description 判断用户意图属于哪个系统：

| 用户意图关键词 | 属于哪个系统 | 应该做什么 |
| --- | --- | --- |
| 财务云(总账、智能会计平台、报表、应收款、应付款、出纳管理、存货核算、固定资产、发票管理、合并报表) 供应链云(采购管理、销售管理、信用管理、库存管理、组织间结算) 开发服务云(BOS运行平台-融合开发) | 金蝶云星空 | 读取 `references/kingdee-k3cloud.md`，按金蝶手册调 k3_* 工具 |
| 依云系统:客户(订单, 订单商品, 回单, 回单明细, 回单结算, 调拨配送, 调拨明细, 三方平台订单, 客户地址, 客户账户, 客户类型, 客户区域, 门店欠结明细, 投诉记录) 门店(门店区域, 门店交账, 交账明细, 库存) 商品(商品分类, 商品单位, 商品属性, 订单商品) 职员(订单, 回单) 单据类型(所有业务单据) 三方平台订单(订单 通过唯一标识关联) 水趣系统:企业/商户(客户(客户地址, 客户微信来源, 用户优惠券(优惠券编码), 电子票账户(电子票基本信息(电子票套餐)), 订单(订单商品)), 门店(拼团商品(拼团分类), 拼团订单(拼团首图), 订单), 商品(订单商品, 拼团商品), 优惠券活动(手机号领券活动(活动配置, 领取记录), 注册送券活动(活动配置, 优惠券编码(用户优惠券)), 电子票(电子票套餐, 电子票账户)) | 依云系统、水趣系统 | **直接调 `linko_ent`**，不加载金蝶手册 |
| 不确定 | — | **按 1.1 系统消歧询问模板**，向用户给出选项，禁止自行选系统 |

核心原则：

1. **金蝶意图第一步必须读手册**：判断用户意图属于金蝶云星空后，先用 `read_file` 读取 `references/kingdee-k3cloud.md` 全文，再开始调用工具；不得凭工具 description 直接猜参数。
2. **工具 description 是权威**：每个 Linko MCP 工具的 description 列明了管辖的业务范围。意图命中哪个 description，就用哪个工具。不要把 A 系统的规则套到 B 系统上。
3. **金蝶手册只管金蝶**：依云/水趣场景不需要金蝶规则，直接调 `linko_ent`。
4. **不确定必须询问，禁止猜**：只要满足下列任一条件，必须停下并按 1.1 模板向用户发起选择，不允许自行选一个系统开始查询：
   - 关键词同时命中两个及以上系统的 description（如"订单/客户/库存/商品/销售订单"等跨系统同义词）；
   - 用户没有点名系统，且意图词不在路由表"独占关键词"里；
   - 在一个系统里查主表/主键为空，准备换另一个系统之前。
5. **数据含义不确定必须问，禁止推测**：工具返回的任何字段、值、枚举、状态码，如果手册或工具 description 里没有明确解释，**不得靠常识或猜测解读给用户**。必须向用户说明"该字段含义需要确认"，或让用户/管理员确认后再解读。这条是红线，违反即事故。

## 1.1 系统消歧询问模板

当满足核心原则第 3 条任一条件时，必须停下并给出固定格式的选项，不要自行查任何一个系统。

### 询问格式

> 你要查的数据可能在多个企业系统里，请确认要查哪个：
> 1. 依云系统（客户订单、回单、调拨、投诉等）
> 2. 水趣系统（拼团、优惠券、电子票等）
> 3. 金蝶云星空（总账、应收应付、库存核算、销售管理等）
> 4. 我也不清楚是什么系统

### 规则

- **直接在回复正文里提问，禁止调用 `ask_user_question` 工具**：IM/Channel 通道不支持该中断，调用会让本轮会话直接中断报错，用户看不到你给出的选项。把上面模板作为普通回复文本发出即可，用户下一条消息就是答案。
- 选项按系统列出，**最后一条固定为"我也不清楚是什么系统"**。
- 只列可能命中的系统，不要把所有系统都塞进去（避免增加用户选择负担）。
- 用户选了具体系统 → 按该系统的工具和手册查。
- **系统选择结果只用于选工具，不写入查询内容**：用户选了某个系统后，调用该系统工具时，`message`（或其他查询参数）里只放用户的原始业务意图（如"查询棒棒糖公司的所有销售订单记录"），**不要**把"依云系统""金蝶云星空"等系统名拼进查询内容。系统名是路由标签，不是查询条件。
- 用户选了"我也不清楚是什么系统" → **禁止随便挑一个系统开始查**，改为追问业务上下文：
  - "你平时在哪个页面/系统里看这条数据？"
  - "有没有单据编号、客户编码之类的线索可以发给我？"
  - "这个数据是业务运营部门用的，还是财务部门用的？"
  追问仍无法判断时，告知用户需要联系管理员确认数据归属，不要继续查询。

## 1.2 数据红线（违反即事故）

以下规则无任何例外，违反任何一条都视为严重事故：

- **禁止推测字段含义**：工具返回的字段名、枚举值、状态码、编码，如果手册或工具 description 没有明确解释，不得用常识、经验或猜测解读给用户。必须告知"该字段含义需要确认"。
- **禁止编造数据**：工具没有返回的值，不得补全；不得把空结果解读为"没有这个客户"或"没有业务发生"——可能是查错了系统或查错了表单。
- **禁止把空结果当作结论**：查到 0 行时，只能如实告知"在当前系统/当前表单/当前条件下没有查到记录"，不得进一步推测业务结论。
- **禁止裁剪或篡改返回数据**：回答必须基于工具返回的原始 `fields`/`data`/`rows`，不得手写常量或人工转抄。

## 第2章 统一返回协议

Linko MCP 工具的查询结果统一为以下格式：

```json
{
  "mode": "inline" | "file"
}
```

- **`mode=inline`**：`rows` 携带明细数据，直接渲染表格或生成摘要
- **`mode=file`**：明细已在服务器 xlsx/csv 文件中，`summary` 是列画像统计（可直接画图），`downloadUrl` 是下载短链——**必须立即下载并保存给用户**，文件会按 `fileExpiresAt` 时间过期

## 第3章 错误处理

- 返回 `Map<Boolean, String>` 格式时（如 `{"false": "查询失败..."}`）：Boolean 是 `false` 表示业务失败，给用户呈现 String 内容；Boolean 是 `true` 表示成功，String 是 JSON 结果需要解析。
- 连续失败 3 次停止，向用户报告阻塞点。
